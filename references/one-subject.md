# A pass on one subject

For a project that already has principles, values and rules, when one subject is open: color and theme, type, motion, one page kind's layout. The subject is usually something an earlier pass put off or never reached, or one corner of the look that accreted while the rest was decided.

## Start from the record

Read these before building anything, and tell the owner what they hold on the subject:

- The reactions file: everything the owner has said that touches the subject, at any stage. Asking again for what's already on file wastes a pick.
- The principles as they stand. This pass doesn't redraft them. Name the ones that govern the subject.
- The rules file and the look's spec, above all its list of what's open: what was put off, what stands in for it, and what else waits on it.
- The tests that name who decided. Each says what a pick here must not undo.

Then write the pass's scope in a few lines and agree it with the owner before building: what's being decided, what's settled and staying settled, and what waits on the outcome. Earlier picks stay closed unless the owner reopens one.

## Which stages run

This table is for a subject that comes down to values: color and theme, type, motion. A pass on one page kind's layout is a different shape, described under the table.

| Stage | In a pass on a subject of values |
|---|---|
| 0. Take an inventory | **Run, on the subject only.** Every value the project has for it today, what job each does, and where the code and the rules disagree. |
| 1. Articulate the apparent design decisions | **Run narrow, or skip.** The glossary stands. Add only the words this subject needs (for color: hue, value, saturation, contrast against the ground, an accent's job), on a short page that annotates two or three of the project's own pages for the subject alone and one or two outside pages that handle it well. Skip it where the owner already uses the words. |
| 2. Speed dating design survey | **Run narrow if the owner's taste on the subject isn't on file.** Ten to twelve outside pages chosen for the subject, on pages like the project's. Skip it where earlier scores and reasons already speak to it. |
| 3. Principles | **Skip the drafting.** List the principles that govern the subject. Raise a fork only for a question the principles don't settle. |
| 4. Test the principles | **Run in full.** This is the pass. One axis a pick, today's page as A, real pages, the owner's pick before the agent's. Draw each pick on more than one kind of page where the subject shows up differently on each. |
| 5. The interaction lab | **Run only if the subject moves or responds to input.** Motion, a control's states, a theme changing. |
| 6. What goes where | **Run one blind test if the pass ends in rules an agent applies with judgment** ("which color a second data series gets"). Skip it if the pass ends only in values. A loss is handled the same way as in a full pass. |
| 7. Write it in and hold it | **Run in full**, in one chunk or two. Close the open item in the spec, move the rules into the rules file, and add the tests. |

**One page kind's layout.** This pass is an inventory of that page kind (what it shows today, and which existing rules already apply to it), then stage 6 and stage 7. Draft that kind's rules from the existing rules and examples, work the page, then blind-test it. The existing example pages go to the agent with the rules from the first test on.

## What changes from a full pass

- **Fewer pages for the owner.** For a subject of values, two at the least (the picks, and stage 7's pull request). Five or six at the most, when the narrow stages 1 and 2 both run, a note asks for a second round, and rules came out of it that need a blind test.
- **Every pick is drawn in the settled look.** Values decided earlier are not options here. Today's page, as built, is A.
- **The subject touches things outside itself.** A color has a job on a chart, on a control and on anything drawn outside the stylesheet. List every place the subject shows up during the inventory, and put the ones a pick can't show on the "calls I made" table.
- **A subject with many settings needs a rule and a check.** A project with several themes can't make each one a pick. Pick on one, write the rule for deriving the rest, and show the rest for a yes or a note.
- **What waits on the subject gets decided or deferred again.** Name each dependent open item on the last page, with the agent's lean.

## An example of scoping

Say an earlier pass left color half decided. Its record might hold:

- Settled: the highlight color is for data only, and controls get an accent of their own.
- Put off: which color that accent is. The theme's blue stands in, and blue is also a chart's second series, so "only interactive things are blue" doesn't hold on a chart.
- Waiting on it: how a second data series is colored.
- A cost already named: a control color is one more color in every theme.
- Reactions on file: one accent doing too many jobs, full color or monochrome for a yes or no, a ramp for an amount.

That pass's inventory is every color in every theme with its jobs. Its picks are the control color and the second series' color, on real pages. Its rule is how a theme derives its colors.
